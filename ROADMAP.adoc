= AssertJ QuickFIX/J Roadmap
:toc:
:toclevels: 2

This roadmap describes direction, not promised dates. GitHub Issues contain public requirements and acceptance criteria.

== Product objective

Provide readable, stable AssertJ assertions for normal QuickFIX/J `Message` values across maintained QuickFIX/J versions. The library must remain a test-scoped consumer tool and must not select an application engine version.

== Maintenance principles

* Preserve public fluent assertion methods within a maintained major version.
* Test the packaged artifact from a separate consumer build.
* Verify supported QuickFIX/J lines from the same source and artifact.
* Keep QuickFIX/J dependencies `provided` so consumers select their engine version.
* Prefer semantic FIX protocol values over version-specific QuickFIX/J aliases.
* Record durable architectural choices in link:docs/adr/README.adoc[architecture decision records].
* Track public work in GitHub Issues. Local `tasks/projects/` directories are working notes only.

== Planned milestones

=== 1.1.0 - Compatibility and release reliability

* Verify QuickFIX/J 2.3.2 and 3.0.2 on Java 11, 17, and 21.
* Remove source coupling to aliases removed in QuickFIX/J 3.0.
* Restore the regression tests that were merged to the historical `master` branch.
* Add dependency convergence, coverage, packaged-consumer, and public API gates.
* Make `mvn --batch-mode verify` the canonical build.
* Publish compatibility, support, contribution, and release documentation.

=== 1.2.0 - Assertion depth

* Add first-class repeating-group and component assertions.
* Improve enum, decimal, timestamp, and malformed-message diagnostics.
* Expand representative coverage across FIX 4.2, FIX 4.4, and FIXT 1.1 with FIX 5.0 SP2.
* Add reusable conditions and extraction APIs where they improve AssertJ composition.

=== 2.0.0 - State isolation

* Replace process-wide custom dictionary overrides with assertion-scoped configuration.
* Remove obsolete or misleading APIs only with migration documentation.
* Review package boundaries so `internal` types are not accidentally treated as public extension points.

== Ecosystem

FixMock records normal QuickFIX/J messages and uses this library for semantic test assertions. The QuickFIX/J Spring Boot starter consumes both released libraries in test scope. The repositories remain independent and use published artifacts to avoid circular source dependencies.

== Priorities

`P0` is a security or release-blocking regression. `P1` is compatibility or reliability work for the next release. `P2` is a valuable assertion, test, documentation, or maintainability improvement. `P3` is exploratory or low-demand work.

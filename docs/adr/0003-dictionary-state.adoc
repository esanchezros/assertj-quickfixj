= ADR 0003: Dictionary override state in 1.x

Status: Superseded for 1.1.0

== Context

`MessageAssert.usingDataDictionary` stores custom dictionaries in a process-wide concurrent registry. Concurrent access is safe, but overrides persist and tests using different dictionaries for the same FIX version can affect one another. Public consumers can rely on the method signature and may rely on its global side effect.

== Decision

Keep `usingDataDictionary` and its global behavior for compatibility, but deprecate it. Add `withDataDictionary` and `withApplicationDataDictionary`. The new methods attach dictionary overrides to one assertion chain. Header, trailer, group, and nested-group assertions share that chain-local registry.

== Consequences

New code can use different dictionaries for the same FIX version in parallel without contamination. Existing code using the deprecated method retains its process-global behavior and limitation. The global registry remains only as a compatibility fallback.

== Alternatives

Changing `usingDataDictionary` to assertion scope was rejected because it would silently remove a side effect on which existing tests may depend. Removing it was rejected as a binary and source incompatibility.
